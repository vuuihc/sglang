# 01 · 并行策略:TP / EP / DP 同时存在吗?谁是谁?

> 对应 **Q1**:"qkv 投影、out 投影是 TP,attn 自己是 DP,ffn 是 EP,是这样吗?"

## 0. 先纠正一个常见误解

你的拆法**部分对、部分错**,而且错在最关键的地方:

> ❌ "qkv 投影 / out 投影是 TP,attention 计算是 DP"

实际上在 `--tp 8 --dp 8 --enable-dp-attention` 这种**满 DP**配置下:
**整个注意力块(qkv 投影 + 注意力计算 + o 投影)全部是 DP,没有任何 TP 切分。**

正确的整体图景是:

| 模块 | 并行方式(满 DP 配置) |
|---|---|
| **注意力块**:q/kv 投影 → 核心 attention → o 投影 | **DP**(整块复制,每卡只算自己那批 token) |
| **MoE 的路由专家(routed experts)** | **EP**(专家分散到各卡) |
| **MoE 的共享专家 / 前几层 Dense MLP** | TP 或全复制(取决于 `moe-dense-tp-size`) |

下面用代码里的公式 + 数字推导,把"为什么是这样"讲透。

---

## 1. 关键公式:attn_tp_size 决定一切

SGLang 在 [dp_attention.py:245-259](../../python/sglang/srt/layers/dp_attention.py) 里这样切分世界:

```python
def compute_dp_attention_world_info(enable_dp_attention, tp_rank, tp_size, dp_size):
    attn_dp_size = dp_size if enable_dp_attention else 1
    attn_tp_size = tp_size // attn_dp_size // attn_cp_size     # ← 注意力内部的 TP 度
    attn_tp_rank = tp_rank % attn_tp_size
    ...
```

记住三个量(先忽略 cp,令 `attn_cp_size = 1`):

```
attn_dp_size = dp_size                 # 注意力被复制成几份
attn_tp_size = tp_size / dp_size       # 每份注意力内部再 TP 切几刀
```

**`attn_tp_size` 就是开关**:
- `attn_tp_size == 1` → 注意力是**纯 DP**,qkv/o 投影都不切,整块复制。
- `attn_tp_size > 1` → 注意力在每个 DP 组内部**再做 TP**,这时 qkv/o 投影才被按 head 切开——也就是你脑中的那个模型。

> 代码注释明确:[dp_attention.py:530](../../python/sglang/srt/layers/dp_attention.py) "tp_size==dp_size (attn_tp_size==1) case is supported (e.g. tp8dp8)"。

---

## 2. 三种配置,手把手算给你看

### 配置 A:`--tp 8 --dp 8 --enable-dp-attention`(本指南推荐)

```
attn_dp_size = 8
attn_tp_size = 8 / 8 = 1     ← 纯 DP！
```

含义:8 张卡,每张卡上都有**一份完整的注意力权重**(wq、wkv、wo 全套),
每张卡只处理分给自己的那批请求,attention 从投影到输出**全程不跨卡通信**。

- ✅ 你说的"qkv 是 TP"在这里**不成立**——qkv 是 DP(复制)。
- ✅ "attention 自己是 DP" —— 对,而且**连投影一起**都是 DP。

### 配置 B:`--tp 8 --dp 2 --enable-dp-attention`

```
attn_dp_size = 2
attn_tp_size = 8 / 2 = 4     ← 每个 DP 组内部 4 路 TP
```

含义:8 卡分成 2 个 DP 组,每组 4 卡。组内这 4 卡**把注意力头切成 4 份**:
- q/kv 投影按 head 列切(column parallel)
- o 投影按 head 行切(row parallel),最后组内做一次 all-reduce

**这才是你脑子里的模型**:qkv 投影 = TP、o 投影 = TP、attention 按头并行。
它只在 `attn_tp_size > 1` 时出现。

### 配置 C:`--tp 8`(不开 dp attention)

```
attn_dp_size = 1
attn_tp_size = 8 / 1 = 8     ← 纯 TP
```

含义:经典张量并行,8 卡把每一层(包括注意力的 qkv/o)都切 8 份。
延迟最低,但对 MLA 模型有致命浪费(见下一节)。

---

## 3. 为什么 MLA 模型偏要用 DP 注意力?(核心考点)

GLM-5 / DeepSeek 用 **MLA(Multi-head Latent Attention)**,它把 KV 压成一个**低秩潜在向量**,
等效于**只有 1 个 KV head**。

现在看纯 TP(配置 C)对 KV cache 的影响:

> TP 切注意力是**按 head 切**的。KV 只有 1 个 head,**切不动**,
> 结果是这唯一的一份 KV cache 被**复制到所有 8 张卡**上。

**数字推导**(以 DeepSeek-V3.2 同架构典型值做示意,GLM-5 量级相近):
- 设单请求、单层 KV(MLA 压缩后潜在维 + rope 维)≈ 576 个元素,FP8 ≈ 576 B
- 61 层 → 单请求单 token 的 KV ≈ 61 × 576 B ≈ 35 KB
- 假设要缓存 128k token 的 1 个长请求 → ≈ 35 KB × 128k ≈ **4.5 GB**

| 配置 | 8 卡里实际存了几份这 4.5 GB? | 浪费 |
|---|---|---|
| 纯 TP(C) | **8 份**(每卡都复制) | 36 GB 显存被 KV 重复占用 |
| DP 注意力(A) | **1 份/卡,但每卡存的是不同请求** | 0 浪费,显存全用来扩并发 |

**结论(背这段)**:
> MLA 只有 1 个 KV head,纯 TP 切不动 KV,只能整份复制 → 8 卡存 8 份重复 KV,白吃显存、压小可并发 batch。
> DP 注意力让每张卡独立持有全套注意力权重、各自处理不同请求的 KV,**KV 不再重复**,省下的显存全变成更大的 KV pool → 更高并发 → 更高吞吐。
> 代价:注意力权重要复制 8 份(但注意力权重很小,远小于 KV cache 和 MoE 权重),完全划算。

所以经验法则(也是文档 [deepseek_v32.md](../basic_usage/deepseek_v32.md) 的建议):
- **高并发 / 吞吐优先 → DP 注意力(配置 A)**
- **低并发 / 极致低延迟 → 纯 TP(配置 C)**

## 3.5 显存账:671B 的 GLM-5,8×H200 到底放不放得下?

> 这是最容易把人绕晕、也是面试最爱追问的一步。先破除一个误解。

### 误解:"DP 就是把整个模型复制 8 份"

很多人一看到 `--dp 8` 就想:GLM-5 是 671B,FP8 ≈ **671 GB**,复制 8 份 = 5368 GB,
H200 才 141GB,**根本放不下,所以肯定不是 DP**。

这个推理的前半段对(671GB 复制 8 份确实放不下),但**结论错了**。真相是:

> **SGLang 的"DP 注意力"从来不复制整个模型,它只复制(很小的)注意力权重;
> 占 97% 参数的 MoE 专家是被 EP 切开的,每张卡只拿 1/8。**
> 所以"DP"和"EP"不是二选一——它们在同一组 8 张卡上**同时存在**,只是作用在模型的不同部分。

你说的"`--tp 8` 其实就是 EP=8"也基本对:`--tp 8` 是**总卡数(world size)= 8**;
加上 `--moe-a2a-backend deepep` 后 `ep_size = tp_size = 8`(DeepEP 的硬约束,见 [02-deepep.md](02-deepep.md)),
于是**专家被切到 8 张卡**。同时注意力走 DP。两件事一起发生。

### 671B 参数到底分布在哪?(精确拆解)

以 671B 这一类(DeepSeek-V3 / GLM-5 同架构)的典型配置计算
(h=7168,256 路由专家,58 个 MoE 层 + 3 个 Dense 层,MLA):

| 组成部分 | 参数量 | 占比 | 并行方式 |
|---|---:|---:|---|
| **路由专家**(routed experts) | **653.9 B** | **97.5%** | **EP 切 8** |
| 注意力(MLA, 61 层) | 11.4 B | 1.7% | **DP 复制** |
| 共享专家(shared expert) | 2.6 B | 0.4% | 复制 |
| Embedding + lm_head | 1.85 B | 0.3% | 词表并行切 8 |
| Dense FFN(前 3 层) | 1.19 B | 0.2% | TP 切 8 |
| **合计** | **≈ 671 B** | 100% | |

**关键观察:97.5% 的参数在路由专家里。** 这就是为什么:
- **EP 切专家**能省下几乎全部显存(671 → 1/8)。
- **DP 复制注意力**几乎不花钱——注意力只占 1.7%,复制 8 份的代价很小。

### 每张卡最终占多少?(FP8,1 byte/参数)

| 组成 | 每卡占用 | 算法 |
|---|---:|---|
| 路由专家 / 8 | **81.7 GB** | 653.9 / 8(EP 切开) |
| 注意力(复制) | **11.4 GB** | 全量复制(DP attn) |
| 共享专家(复制) | 2.6 GB | 全量复制 |
| Dense / 8 | 0.1 GB | TP 切 |
| Embedding / 8 | 0.2 GB | 词表并行 |
| **每卡权重合计** | **≈ 96 GB** | |

H200 单卡 **141 GB** → **剩 ≈ 45 GB** 给 KV cache + 激活 + CUDA Graph buffer。
**放得下,而且还很宽裕。** ✅

对照一下两个极端:
- **朴素全复制(真正的"整模型 DP")**:每卡要 671 GB → **远超 141GB,不可能**。这就是你担心的情况。
- **EP 切专家后**:每卡 ≈ 96 GB → **轻松装进 141GB**。

### EP=8 到底"省"了多少?

就专家这部分而言:**从每卡 653.9 GB 降到 81.7 GB,省了 ≈ 572 GB/卡(降为 1/8)。**
正是这一步让 671B 模型"装得下"。

> ⚠️ 注意 TP 和 EP 对 MoE 权重的**总显存节省其实一样**(都是把专家均摊到 8 卡,每卡 ~82GB)——
> 区别在**切法和通信**:TP 把每个专家的矩阵按列/行切碎(每卡都参与每个专家);
> EP 把整颗专家整个分给某张卡(每卡只管自己那批专家),配 all-to-all 路由 token。
> 对 MoE 来说 EP 的通信模式更高效,所以大规模 MoE 选 EP。

### DP 注意力的"代价"与"收益"对账(回扣 §3)

DP 注意力相对纯 TP,在**权重**上多花了钱、在 **KV cache** 上省了大钱:

| | 纯 TP(配置 C) | DP 注意力(配置 A) |
|---|---|---|
| 注意力权重/卡 | 11.4 / 8 ≈ **1.4 GB** | **11.4 GB**(复制,多花 ~10GB) |
| KV cache | **被复制 8 份**(MLA 1 个 KV head 切不动) | **不复制**,每卡只存自己请求的 KV |
| 净效果 | 省一点权重,**KV 巨浪费** | 多花 ~10GB 权重,**换回几十 GB 的 KV 空间** |

> **一句话**:DP 注意力是"花 10GB 买几十 GB"——用一点点注意力权重的复制开销,
> 换掉 MLA 在纯 TP 下那份巨大的 KV cache 重复浪费。所以高并发场景一定选它。

### 这 ~45GB 余量能缓存多少 token?

扣掉激活 + CUDA Graph buffer(`--chunked-prefill-size`、`--cuda-graph-max-bs` 决定,见 [04](04-memory-and-scheduling.md))
约 15–20 GB 后,KV pool ≈ **25–30 GB**。MLA 单 token KV ≈ 35 KB(见 §3 推导):

```
30 GB / 35 KB ≈ 85 万 token 的缓存额度
```

- 短请求(~1k token)→ 可并发约 800+ 个。
- 128k 长请求 → 同时约 6–8 个。
这正是 [04-memory-and-scheduling.md](04-memory-and-scheduling.md) 里 `mem-fraction-static`
和 `max-running-requests` 各自在管的东西。

> 注:上面所有数字按 DeepSeek-V3/GLM-5 同架构典型值推算(总量精确对齐到 671B),
> 用于建立量级直觉;GLM-5 官方 config 的层数/维度若有出入,结论(每卡 ~90–100GB、8×H200 放得下)不变。

## 3.6 为什么专家比注意力大 60 倍?—— 从稠密模型的"2 倍"说起

> 这一节回答上一节那个反直觉的数字:注意力只占 1.7%,专家占 97.5%。
> 关键是先记住稠密模型里 FFN 和注意力的比例,再看 MoE 怎么把它放大。

### (1) 稠密 Transformer:FFN ≈ 2× 注意力(经典推导)

设 hidden 维度为 `d`,一层里:

**注意力(MHA)** —— Q、K、V、O 四个投影,每个 `d×d`:
```
W_Q + W_K + W_V + W_O = 4 · d²
```

**FFN(经典,中间层 = 4d)** —— 升维 + 降维两个矩阵:
```
W_up(d→4d) + W_down(4d→d) = 4d² + 4d² = 8 · d²
```

**比值 = 8d² / 4d² = 2×**。你记的没错:**FFN 是注意力的 2 倍**,两者**同一个数量级**。

> SwiGLU 变体(Llama/GLM 用的)有 3 个矩阵(gate/up/down),但中间层会缩到 ≈ (2/3)·4d ≈ 2.67d
> 来对齐参数量,算下来 3 · d · 2.67d ≈ 8d²,**还是 ~2×**。设计上就是奔着这个比例去的。

代入 `d = 7168` 验证一下,也和 §3.5 的实测对得上:
- 稠密注意力 `4d² ≈ 205M`,而 MLA 实测 `≈ 187M` —— **同量级**(MLA 靠低秩压缩还略小)。
- 稠密 FFN `8d² ≈ 411M`,约 2× 注意力。✓

### (2) MoE 怎么把"2×"放大成"60×"?—— 靠数量,不是靠变大

MoE 把这一个 FFN,换成 **E 个小专家**。注意 GLM-5 用的是**细粒度小专家**:
每个专家的中间层 `m = 2048`,**远小于** `d = 7168`(只有约 0.29d)。

| | 参数(每 MoE 层) |
|---|---:|
| 注意力(1 份) | 187 M |
| **单个专家**(SwiGLU 3 矩阵 = 3·d·m) | **44 M** ← 比注意力**还小**! |
| 路由专家(**× 256 份**) | 256 × 44M = **11.3 B** |
| **比值** | **≈ 60×** |

**反直觉的核心**:60 倍**不是因为每个 FFN 变大了**(单个专家 44M 比注意力 187M 还小),
而是因为**存了 256 份**。每个 token 只激活其中 8 份(top-8)。

> 一句话:**稠密:FFN = 2× 注意力;MoE:FFN = 256 份小专家 = ~60× 注意力。**
> 差别全在"× 专家数"。

### (3) 由此引出 MoE 的灵魂:总参数 vs 激活参数

既然存了 256 份却只用 8 份,MoE 就有了**两个**参数量,分别决定不同的成本:

| | 数值 | 决定什么 |
|---|---:|---|
| **总参数** | 671 B | **显存 / 存储**(必须全存 → 这是要 8×H200 的根因) |
| **激活参数**(每 token 实算) | **≈ 37 B** | **算力 / 延迟**(只算 top-8 专家 + 共享 + 注意力) |

激活量推导:
```
注意力(全激活)            ≈ 11.4 B
每 MoE 层激活 = (8 路由 + 1 共享) × 44M ≈ 396M，× 58 层 ≈ 23 B
Dense 层 + lm_head        ≈  2 B
合计                      ≈ 37 B   ← DeepSeek-V3 著名的“671B 总参 / 37B 激活”
```

### (4) 那它"相当于"多大的 Dense 模型?—— 分三层,别只看一个

MoE 把**能力**和**算力**解耦了,所以"等效多大"要分开说:

| 维度 | GLM-5 (671B/37B) 相当于 | 原因 |
|---|---|---|
| **算力 / 延迟(FLOPs)** | **~37B Dense** | 每 token 只算 37B → 跑起来像小模型,**便宜** |
| **显存 / 带宽** | **671B**(满血) | 256 份专家必须全存 → 部署是**显存瓶颈** |
| **能力 / 效果** | **远超 60B,约 150B+ Dense** | 256 个专家存了海量专业知识,router 按需调度 |

最后一格的经验法则(rule of thumb,非定律):等效能力 ≈ √(激活 × 总参) = √(37 × 671) ≈ **158B**。

> **结论(背这段)**:GLM-5 用 **~37B 的算力成本** + **671B 的显存成本**,换来约 **150B+ Dense 的能力**。
> 它不是"60B Dense",而是"**花小模型的计算钱、大模型的显存钱,买大模型的脑子**"。
> 这也解释了为什么部署 GLM-5 的核心矛盾是**显存(存储)**而非算力——
> 以及为什么 EP 切专家(省显存)比省算力重要得多。

## 4. 那 MoE(FFN)部分呢?—— EP

注意力解决了,FFN 这边 GLM-5 是 **MoE**:N 个路由专家 + 少量共享专家。

- `--ep 8`(或 `ep_size = tp_size` 时由 DeepEP 隐式成立)把**路由专家分散到 8 张卡**:
  每张卡只存 `总专家数 / 8` 个专家的权重。
- 一个 token 选中 top-k 个专家,这些专家可能在别的卡上 → 需要 **all-to-all** 把 token 送过去算、再送回来。这就是 DeepEP 干的事(见 [02-deepep.md](02-deepep.md))。
- **前几层 Dense MLP / 共享专家**不是 MoE,用 `--moe-dense-tp-size` 控制:
  代码 [deepseek_v2.py:2035](../../python/sglang/srt/models/deepseek_v2.py) 里 `enable_moe_dense_fully_dp()` 为真时这部分也走 DP(`mlp_tp_size=1`),否则按 TP 切。

## 5. 一张总表(满 DP + EP 配置,即配置 A + `--ep 8`)

```
请求到达 → 按 DP rank 分发到某张卡
   │
   ▼ 【注意力块 = DP】每卡用本地完整注意力权重，算自己这批 token
   │   q/kv 投影(DP) → MLA attention(DP) → o 投影(DP)   ← 无跨卡通信
   │
   ▼ 一次 all-gather / all-to-all，把 token 重新分布到“按专家”的布局
   │
   ▼ 【MoE = EP】DeepEP dispatch → 各卡算本地专家(DeepGEMM) → DeepEP combine
   │
   ▼ 再分布回“按 token(DP)”的布局，进入下一层
```

> 一句面试话:**"注意力 DP、专家 EP、两者之间靠 all-to-all 切换数据布局"** —— 这就是 DeepSeek/GLM-5 在 SGLang 上的并行骨架。
> 你最初说的"qkv=TP"只在 `attn_tp_size>1`(如 tp8dp2)时才对;满 DP(tp8dp8)下注意力整块是 DP。
