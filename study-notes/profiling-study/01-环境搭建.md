# 01 · 环境搭建(以及踩到的三个坑)

## 硬件选择:为什么是 H20

国内可租:RTX 4090D(24GB)、A100(80GB)、H20(96GB)、H800(80GB)。三类卡画像差别巨大:

| 卡 | 架构 | 算力 fp16 | 显存带宽 | 显存 | FA3 | 一句话 |
|---|---|---|---|---|---|---|
| RTX 4090D | Ada **sm89** | 中 | ~1 TB/s | 24GB | ❌ | 算力够、显存小、便宜 |
| A100 | Ampere **sm80** | 中高 | ~2 TB/s | 80GB | ❌ | 上代旗舰 |
| **H20** | Hopper **sm90** | **极低(~148T,被砍)** | **~4 TB/s(满血)** | 96GB | ✅ | **带宽富、算力穷、显存大** |
| H800 | Hopper **sm90** | 高(~990T) | ~3.4 TB/s | 80GB | ✅ | 均衡高端,NVLink 被限 |

H20 的"带宽富、算力穷"恰好是 **decode(memory-bound)的甜点**,且算力弱让 host 占比相对更突出,适合学习;又是国内部署主力卡,优化有真实受众。

## 坑 1:GPU 架构墙 —— 最新 sglang 不支持消费/上代卡

最新 `sglang 0.5.13.post1` 硬依赖 `sglang-kernel==0.4.3`(注意:kernel 包已从 `sgl-kernel` 改名为 `sglang-kernel`),
而这个预编译 wheel **只编了 sm90 + sm100**:

```
ls site-packages/sgl_kernel/   →  sm90  sm100   (没有 sm89!)
```

后果:**4090D(sm89)、A100(sm80)装上后 `import sgl_kernel` 直接报错**:
```
[sgl_kernel] CRITICAL: Could not load any common_ops library!
Compute capability: 89 → Expected variant: SM89 ... found: sm100 only
```
旧的 `sgl-kernel`(带连字符)最高只到 0.3.21,属于旧 sglang 线。

**结论:最新 sglang 实际只支持 Hopper(sm90)及以上。** → 必须用 H20/H800,4090D/A100 要么装旧版、要么源码编译。

## 坑 2:torch 2.11.0 的 inductor bug

最新 sglang 把 torch 升到 **2.11.0+cu130**。它的 `_inductor` 有个 bug:
`torch._inductor.kernel.flex_attention` 被导入时重复注册同名 Triton 模板:
```
AssertionError: duplicate template name
```

触发链:sglang 默认开 **piecewise cuda graph** → `install_torch_compiled` → import torch inductor → 崩。

**两个修法,缺一不可**(都已写进环境):
```bash
export TORCHDYNAMO_DISABLE=1                 # 挡住 import 期触发(deep_gemm 的 @torch.compile)
# 运行期再用 sglang flag 挡住 piecewise cuda graph:
python -m sglang.bench_one_batch ... --disable-piecewise-cuda-graph
```
> 注意:`--disable-piecewise-cuda-graph` 只关"基于 torch.compile 的分段图",**常规 cuda graph 仍然开着**(这点很重要,见 03/04 文档)。
> `TORCH_COMPILE_DISABLE=1` 单独没用,必须用 `TORCHDYNAMO_DISABLE=1`。

这俩开销为零、对 profiling 无副作用(sglang 主路径用自己的 cuda graph,不依赖 torch.compile)。

## 坑 3:把环境做成可复用镜像(省下次机器时间)

AutoDL 实例**本身就跑在容器里,没有 docker**,所以不能 docker-in-docker。复用环境的正路是 **AutoDL 控制台「保存镜像」**(存系统盘)。

为让镜像"开机即用",在系统盘写了 `/root/sglang_env.sh` 并加进 `.bashrc` 自动 source:
```bash
export LD_LIBRARY_PATH="/root/miniconda3/lib/python3.12/site-packages/nvidia/cu13/lib:$LD_LIBRARY_PATH"  # libnvrtc.so.13
export HF_ENDPOINT=https://hf-mirror.com         # 国内拉模型镜像
export HF_HOME=/root/autodl-tmp/hf
export SGLANG_TORCH_PROFILER_DIR=/root/autodl-tmp/profile_log
export PATH=/root/miniconda3/bin:$PATH
export TORCHDYNAMO_DISABLE=1                      # 坑 2 的修法
```

**关键洞察:在 4090D 上装好的这套环境(kernel 含 sm90),存成镜像后能直接在 H20/H800 上即插即用。**
所以即便 4090D 自己跑不了最新 sglang,装环境 + 存镜像的工作没白费 —— 我们正是这么从 4090D 迁到 H20 的,H20 上 `import sgl_kernel` 一次通过。

### 安装命令(国内走清华镜像,别加 pypi.org 兜底)
```bash
pip install -U sglang -i https://pypi.tuna.tsinghua.edu.cn/simple --default-timeout=120 --retries 10
```
> 教训:加 `--extra-index-url https://pypi.org/simple` 会让大 wheel 去 files.pythonhosted.org(美国)下,频繁 ReadTimeout。清华镜像本身就全量镜像了 PyPI,单独用它最快。

### 复用流程
1. 控制台 → 实例 → **关机** → 「更多」→「保存镜像」(只存系统盘,`/root/autodl-tmp` 缓存不进镜像)。
2. 释放当前卡。
3. 新建实例 → 选目标卡 → 镜像选「我的镜像」→ 开机即用。
