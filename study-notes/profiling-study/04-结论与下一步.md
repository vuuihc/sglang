# 04 · 结论与下一步

## 诚实的总览结论

把整条链路实测下来,结论很干净:

1. **模型前向路径已经被 sglang 优化透了。**
   - cuda graph 消掉了 host 发射开销(利用率 38%→92%)。
   - 关键算子(add+RMSNorm、QK-norm、RoPE)都已融合成单 kernel。

2. **H20 上 batch=1 decode 的残余瓶颈是硬件算力。**
   - 82% GPU 时间在 nvjet GEMM,这是 H20 弱 FLOPS 下的**硬件墙,不是改代码能拿下的软件优化**。
   - 唯一相关的 GEMM 替换(#22392)还是个**在途 PR**,且只对 FP8 生效(我们是 bf16)。

3. **所以便宜的可提交 PR 不在前向路径里。**
   它在 `bench_one_batch` **根本没触发**的真实 serving 路径:`scheduler` / `tokenizer` / `detokenizer` 的 host 开销。cuda graph 也盖不住那部分(它在图外)。

> 这条结论和最初**静态扫描**(两个 scan agent 读代码)得到的"热路径已成熟、机会在 host 侧调度逻辑"完全吻合 —— 现在是用 GPU 实测交叉验证了。这是好事:两条独立方法收敛 = 结论可信。
